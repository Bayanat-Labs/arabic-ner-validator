Arabic NER Offset Validator

Check Arabic named-entity annotations before training: offsets counted in the wrong unit, text that changed after annotation (NFC, NFKC, tatweel, line breaks, byte order marks), spans that cut a letter from its haraka or a clitic from its word, overlaps, nesting and BIO/BIOES/BILUO tag errors.

Everything runs in this page. The file you open or the text you paste is not uploaded or stored; closing the tab or pressing Clear discards it.

The Arabic text has not yet been reviewed by a native Arabic writer; the English governs.

1. Input

A text box turns CRLF line breaks into LF. To check line breaks or a byte order mark, open the file instead of pasting it.

The offset unit is never guessed. If you are not sure, run once: the report says which unit fits.

    How it works

    • Offsets are read in the unit you declare (code points, UTF-16 units, UTF-8 bytes or grapheme clusters) and checked against the text exactly as stored.
    • When a span does not fit, the validator tries the other units and the usual changes to a text (NFC, NFKC, tatweel or diacritic removal, CRLF and LF, a byte order mark). If exactly one reading makes the span fit, it names it and suggests new offsets; if several readings disagree, the span stays an error with no suggestion.
    • Span edges are checked for grapheme clusters (a letter and its harakat), words and tokens, the clitic policy, bidi and zero-width controls, whitespace and punctuation. Overlaps, nesting, labels and tag sequences are checked per record.
    • This page runs a JavaScript port of the Python package; both give the same report on every test case.
